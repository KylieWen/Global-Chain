# 多角色协作与商品分层：讨论记录

记录日期：2026-10-23。本文区分用户已确认的方向与待讨论的方案；不是已经交付的注册、管理端或协作功能。当前程序仍使用只读发布资料，没有新增账号、数据库或写入接口。

## 用户表达与已确认事项

- 用户提出：平台部署后，自己需要一个操控端，公众有用户端；希望引入协作者补充商品、产业链上下游，也允许企业注册申请加入链条中的环节。
- 企业功能顺序已确认：“两者都要，但先完成申请与审核”。先申请加入已有环节、审核展示，之后再讨论企业自己的供应链页面及邀请上下游。
- 审核顺序已确认：“先由我审核，之后再授权可信协作者”。不把普通注册等同于取得审核权。
- 用户提出按角色组织界面：产业参与者优先看详细上下游、企业和联系方式；高校研究者优先看研究资料、来源，企业作为辅助。用户希望借此兼容公众理解世界商业逻辑与产业链查询两种用途。
- 用户认为仅由自己和助手补完全球资料不可行，需要用户投稿与协作。
- 用户特别指出：详细作用说明应在悬停、停留后浮现；地图抓取不准确、部分国家只出现方框；希望寻找成熟商品分类或层级体系。

以上是用户表达的本意摘要；下列流程、名称和技术选择是 Codex 提案，尚不能写成用户原始愿景。

## 建议：浏览视角与写入权限分开

同一套网站和后端可以同时提供公众界面、投稿工作区、企业资料区和管理区；第一版不需要拆成几台服务器。“管理端”是你的操作界面，“服务端”是校验、保存和发布资料的后端，两者不是同一个概念。

| 浏览视角（建议名称） | 默认入口与信息顺序 | 编辑资格 |
| --- | --- | --- |
| 看懂世界 | 世界地图、商品拆解、材料与国家故事 | 浏览无需投稿权限 |
| 调研研究 | 统计口径、来源、年份、研究快照与版本对照 | 可另行申请协作 |
| 产业上下游 | 工艺、材料、设备、企业能力和官方联系方式 | 企业/协作者另行审核 |

建议首次进入给出三个简短入口，可跳过、可切换；后续在导航中保留视角切换。不同视角复用相同事实和来源，只改变入口、排序及默认展开内容，不维护相互矛盾的三份数据。是否要求首次必须选择、是否记住偏好、名称及默认入口仍待用户决定。

权限建议独立设置：浏览者、投稿协作者、企业资料维护者、受邀审核者、平台管理员。一个账号可同时具有多个身份；声称自己是教授或产业人士只改变浏览视角，不自动赋予审核权。

## 建议：先完成一个提交与审核闭环

以一家压缩机企业为例：企业申请账号和代表资格，选择已有“压缩机”环节，填写所在地、产品/工艺能力、官方产品页和联系入口，并附资料日期与来源。提交后进入你的待审核列表；你查看新增/修改对照，要求补充或批准。批准后，公众地图的该环节出现这家企业的能力资料与官方入口。

企业具备“生产压缩机的能力”，与“确实向某品牌供货”应作为两种不同声明审核。仅凭企业自荐或双方都在同一地图上，不能自动画成已核实供货关系。自述资料、身份审核、能力证据和供货证据分别记录，不用一个“认证”徽章混在一起。

协作者采用相同的提案流程：选中现有商品/环节，提交新增节点、关系、纠错或来源，说明改动理由和适用年份。提交形成独立修订，不直接覆盖公开资料；你批准后形成可追溯发布版本。对重复节点、多人同时修改、撤回、更正和回滚需在实现前约定规则。

建议第一版管理区优先有：待审核列表、改动前后对照、来源预览、要求补充、批准/驳回及理由、发布/回滚记录。企业邀请上下游共同维护、受邀审核者授权、通知与团队协作放在下一阶段。现阶段不增加站内询价、撮合、交易或运行时 AI。

## 商品分类研究：推荐多维组合

本次检索日期为2026-10-23，仅记录一手标准与原始研究，不把检索结果直接灌入发布数据。

| 体系 | 能解决的问题 | 不能直接解决的问题 |
| --- | --- | --- |
| 联合国 CPC | 统一识别商品与服务所属类别 | 本身不证明具体企业的供货关系，也不是一条产品拆解路线 |
| 联合国 BEC Rev.5 | 将经济用途独立区分为中间消费、最终消费、固定资本形成，并提供加工等维度 | 不能把所有 CPU 永久归为某条手机链的某个供应层级 |
| GS1 GPC | 商品目录的 Segment/Family/Class/Brick 与属性体系 | 分类树层次不等于上下游距离 |
| 企业供应网络中的 Tier 1/2/3 | 相对于某个企业/链主的直接、间接供应层级 | 不是世界上每一种商品永久不变的等级 |
| 上游度研究（Upstreamness） | 以投入产出表衡量产业距最终用途的平均距离 | 是产业统计指标，不是单个型号、工厂或一条已知链路的准确步数 |

推荐给 GlobeChain 的四个维度（本平台提案，非新造国际标准）：

1. **它是什么**：保留当前商品ID与海关分类，未来按明确版本映射 CPC；目录需要时再采用 GPC。不同体系的映射必须保留一对多、不匹配和人工审核状态。
2. **用来做什么**：借鉴 BEC 的中间投入、最终消费和资本品语义，记录所处用途与依据；同一种物品可因实际用途而不同。
3. **技术上是什么形态**：原料、加工材料、零部件、总成/模块、成品；设备、能源、服务另行表示。保留不适用/待判断，不强迫所有对象塞进一条单线。
4. **在这条链里处于哪里**：相对当前商品或链主显示上游层级与具体路径；部件层级与企业供应 Tier 分开。存在多条路径、回收循环或未知关系时，如实显示，不仅用最短距离宣称真实供应层级。

示例：家庭购买手机时，可显示最终消费用途和整机形态；屏幕总成是手机的模块，芯片是部件。芯片放到半导体产业视角也可以是该产业的产成品，并有汽车、计算机等多种下游。生产设备即使制造链较上游，也不应按“原料”处理。此处是分类方法示例，不是新增具体企业关系或商品统计结论。

现有数据采用多个海关版本，BEC对应表也有适用版本。实现时必须核对版本对应和产品范围；不能把海关编码位数、拆解深度或图上距离直接当成 BEC/Tier 代码。

### 一手来源

- [UNSD：BEC Rev.5 官方说明及2018版手册入口](https://unstats.un.org/unsd/trade/classifications/bec.asp)：用途维度独立于经济类别。
- [UNSD：BEC5 与 CPC/HS 对应说明，2018-11-08](https://unstats.un.org/unsd/classifications/Econ/tables/CPC/CPCv21_BEC5/Note_on_BEC_Correlations_08_Nov_2018.pdf)：列出用途、加工、规格与耐用性维度及适用对应。
- [UNSD：CPC 官方资料与版本](https://unstats.un.org/unsd/classifications/Econ/CPC.cshtml)。现行3.0资料与历史2.1应按实际适用映射选择，不能仅替换版本名。
- [GS1：How GPC works](https://www.gs1.org/standards/gpc/how-gpc-works)。官方搜索索引可读，直接页面访问返回403；可结合[GS1 GPC实施指南](https://www.gs1.org/sites/default/files/gpc_development_and_implementation_1.pdf)核验结构。
- [Motherson：2024-09-16公司发行资料](https://www.motherson.com/storage/Corporate%20Announcements/FY2024-25/Preliminary_placement_document_16.09.24.pdf)：汽车行业 Tier 1/2/3 分工示例，只用于解释惯例，不当作覆盖所有行业的正式产品分类标准。
- [Antràs、Chor、Fally、Hillberry（2012），Measuring the Upstreamness of Production and Trade Flows，NBER](https://www.nber.org/papers/w17819)：以产业距最终用途平均距离构造上游度；[AEA正式发表页](https://pubs.aeaweb.org/doi/10.1257/aer.102.3.412)。本平台目前没有所需完整投入产出数据，不计算或填充该指标。
