## 3. 总体评价与需求对照

### 3.1 五个维度

**产品方向**

- 优点：「商品 → 供应链 → 国家账本 → 来源」的叙事清楚；"代表性路线"与"官方统计"分层；空调的产业上下游加官方入口，是同类作品少有的区分点。
- 问题：定位三套并存（见 2.4）；首页首屏与 `/demo` 三分钟路径仍只讲手机，**完全没有空调/供应链参与者**（P0-3）；进出口指南实现很薄（P0-5）。

**交互逻辑**

- 优点：页面间有上下文参数传递（周期、版本、内容版本提示条）；国家形状带 `role=button`、`tabIndex`、`aria-label` 和 Enter/Space 响应；地图记录列表与连线悬停联动。
- 问题：未收录国家点击无反馈；筛选走整页服务端重渲染且**没有任何 pending 反馈**；没有 `error.tsx`/`loading.tsx`；搜索页无页内输入框；导航无产业入口；命名不一致；材料页筛选无选中态。

**视觉体验**

- 优点：5 个商品插画风格一致（products 截图）；地图首屏可见；整体层级清楚。
- 问题：地图默认着色颠倒（P0-1）；图例缺类；英文眉标约 35 种且有内部词；商品卡"已发布"徽标无信息量；数量单位"亿 kg"。

**数据覆盖**：见第 5 节附表。核心事实：15 个国家与地区；18 条双边贸易观察，只覆盖 3 个国家对；106 条代表性连线全部无数值；国家账本 26 页中 11 页没有任何指标或贸易行。

**工程质量**：优点是 strict TS、0 处 `any/@ts-ignore/TODO`、zod 契约、不可变 release + 校验脚本、CI 含 lint/typecheck/test/build、数据脚本带来源哈希。短板是无 UI/E2E 测试进 CI、巨型文件、展会用 dev server 启动、文档陈旧。

#### P0-1 地图默认状态下，所有未收录国家被渲染成"已选中"，重点与背景颠倒

- **证据**：[A] 代码 + 像素
- **位置**：`apps/web/components/world-country-map.tsx` 第 93 行 `country?.id === filters.country`；`apps/web/app/globals.css` 第 947–950 行。
- **根因**：未收录国家的 `country` 是 `undefined`；没选国家时 `filters.country` 也是 `undefined`；`undefined === undefined` 为 `true`，于是 `selected` 类被加到所有无数据的国家上。
- **证据细节**：`.selected` 的填充 `#599e92` = RGB(89,158,146)，截图 `map-1440.png` 中巴西、撒哈拉地区采样像素正是 (89,158,146)；有数据国家是 `.has-data` 的 `#486e7a` = (72,110,122)，在画面上**更暗**。图例只有两类（参与供应链、仅有账本），画面实际有三类色。点击任意国家后，其余国家变回 `#274554`，地图整体"闪变"。
- **影响**：评委第一眼看到的是"没数据的国家最亮"，与你要的"高亮有数据的国家"相反。
- **复现**：打开 `/map?product=generic-smartphone&layer=supply-chain`，不点任何国家，截图；再点"中国"，再截图，对比巴西颜色。DevTools 控制台执行 `document.querySelectorAll('.map-country-shape.selected').length`，预计现状远大于 0。
- **改进**：把判断改为 `country && country.id === filters.country`；顺手检查同文件中其余 `country?.id ===` 比较（`hovered` 一项因初值为 `null` 不受影响）。
- **验收**：
  1. 默认状态下 `.map-country-shape.selected` 数量为 0；
  2. 未收录国家为 `#274554` 暗底，有数据国家明显比它亮；
  3. 选中国家前后，未选中国家颜色不变；
  4. 新增一条渲染测试覆盖"无选中国家时 selected 数为 0"（需要引入组件渲染测试，见 P2-2；或先在 Playwright 冒烟里加断言）。
- **成本**：S（一行改动 + 一条断言）

#### P0-2 展会现场的启动方式不稳

- **证据**：[A] 脚本；实际耗时 [C]
- **位置**：`scripts/start-demo.ps1`
- **问题**：
  1. 启动的是 `pnpm run dev`（Next **开发服务器**），路由按需编译，评委每点一个新页面都可能卡一下；`map` 等 10 个页面是 `force-dynamic`，每次筛选整页重算；
  2. 每次启动**先删除 `apps/web/.next`**，等于强制冷编译；
  3. 就绪探测是 30 次 × 500ms = **15 秒**，超时即杀进程并抛错，冷编译很可能不够；
  4. 兜底路径写死了作者机器上的 `E:\EDA\corepack.cmd`；
  5. 无任何"断网"或"服务器挂了"的预案。
- **改进**：
  - 提供 `start-demo` 的生产模式：`pnpm build` 一次，演示时 `pnpm start`；不再删缓存；超时放宽到 90–120 秒；去掉写死路径，找不到 corepack 时给出明确提示。
  - 启动后自动**预热**演示路径上的每个页面（脚本逐个 `curl`）。
  - 准备兜底：一段 3 分钟屏幕录像 + 关键页面静态截图，放桌面。赛制文件也建议准备本地环境或视频，并要求如实说明运行情况。
- **验收**（需在展会用的笔记本上实测并记录）：
  1. 双击到首页可交互 ≤ 30 秒；
  2. 预热后 `/`、`/map`、`/products/*`、`/products/generic-home-air-conditioner/industry` 首次访问均 < 2 秒；
  3. **拔掉网线**后，演示路径全程可用，浏览器 Network 面板无外部域名请求（字体、地图瓦片等；我没验证是否存在外部请求）。
- **成本**：M
