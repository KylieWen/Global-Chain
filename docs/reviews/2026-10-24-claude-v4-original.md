## ③ 发现

> 复现脚本都是我在 `/tmp` 里写的 Python，逻辑很短，Codex 可以用同样口径重算（见每条的"复现"）。统计口径：只读 `active-manifest.json` 里的 5 个 fixture 的 `industryNetwork.topics / relations / organizations`。

### P0（影响评委观感或"现场所说与所见不一致"）

#### P0-1 手机产业网络是 19 个孤立块，默认入口是死胡同 · [亲验]

- **统计**（弱连通分量）：手机 69 环节 = 一个 28 节点块 + 一个 6 节点块 + 一个 3 节点块 + **16 个 2 节点块**（一个工序 + 一个设备类别，互相只连对方）。
- **工序完整度**：32 道工序中，有投入的 15、有设备的 18、有产出的 15，**同时具备三者的 = 0**。对照：棉 T 恤 11/12、大豆油 8/9、电动自行车 8/8、空调 10/16。
- **手机没有"智能手机"产品节点**（其余四商品都有）。产业网络里五条工艺链（封装、摄像模组、PCB、机身、电池包）只是各自存在。
- **默认入口**：`defaultTopicId = technical-step-process-incoming-inspection` → "**来料与晶圆检查**"，上游 2、**下游 0**。评委点"手机 → 产业与企业"第一眼看到的是晶圆来料检验。
- **企业层**：6 家企业（DISCO、ASMPT、K&S、TOWA、Advantest、Onto）9 个入口全是设备类别节点（入度 0、出度 1，指向单个工序）。其中 **Advantest 的"电性能测试"与 Onto 的"最终检测与计量"各自落在 2 节点孤岛**：点进去既无上游也无下游。
- **影响**：手机是最深的商品，也是评委最可能点的商品，但"产业与企业"这一页给不出一条连续的"材料→工序→设备/应用"。
- **建议**（按工作量）：
  1. 展位前（零代码）：演示手机产业页时，用页内下拉**手动选"封装集成"**（我统计其度数 4，在 28 节点主块里）作为起点，别用默认入口。
  2. 近期（需新 release）：把 `defaultTopicId` 改成主块里度数高且上下游都有的节点；给工序之间补 `process → process` 顺序关系（现在 5 个商品**全部 0 条**工序间关系，`manufacturingProcessSteps` 里是有顺序的，网络没投影进去）；补一个"智能手机"根节点。
  3. 不要为了连通而编造供应关系——工序顺序来自已有 step 顺序，是技术关系，不是商业关系。
- **验收**：手机网络弱连通分量 ≤ 5；默认入口上下游各 ≥ 1；至少 1 条 `原料/部件 → 工序 → 下一工序 → 部件` 的 ≥ 4 跳路径可点击走通；Advantest/Onto 入口能点到上下游。
- **复现**：对 `releases/generic-smartphone/globe-chain-smartphone-2026.6/fixture.json` 的 `industryNetwork` 建无向图求连通分量；对每个 `kind=process` 统计 `process_input` 入边、`equipment_for` 入边、`used_in` 出边。

#### P0-2 空调 86 环节是两个互不相连的子网，且含重复节点 · [亲验]

- **统计**：分量 45 + 41。**45 个是 2026.5 之前已有的网络，18 家企业全部挂在它上面；41 个是 2026.6 新增的"通用制造链"（1997 DOE 来源），0 家企业、与前者无任何关系边。** 审计文件 `review-audit.json`：before 45/67 → after 86/107，新增恰好 41 环节/40 关系。
- **重复**：同名"**家用房间空调**"出现两次（`room-air-conditioner`、`technical-item-generic-home-air-conditioner`，分属两个子网）。语义重复更多：`回弯管钎焊`（旧）↔ `扩管与回弯管钎焊`（新）；`空调与制冷压缩机` ↔ `压缩机`；`空调智能控制器` ↔ `控制器`；`铝翅片与铝卷材` ↔ `铝片/卷材`。（后几对是我按名称判断的语义重复，Codex 请逐对确认是否同一概念。）
- **影响**：搜索"压缩机/控制器/换热器"会同时命中新旧两份；评委从新子网进去时**看不到任何企业**，从旧子网进去时看不到完整制造顺序。这正是你最关心的"蒸发冷厂商找冷排/金属管上游和制冰机下游"的主场景——它**只在旧子网里**（雪人集团 → 蒸发式冷凝器/制冰机；下游用途来自 2026-10-23 补的公开技术案例），没有受影响，但新子网稀释了它。
- **建议**：
  1. 展位前（零代码）：现场只走旧子网路径（空调产业页默认入口 `铜管铝翅片换热器`，或直接选"蒸发式冷凝器"）。
  2. 近期：把 41 个新环节与旧网络做**显式合并映射**（同义节点合并，保留 DOE 1997 作为该节点的额外来源，而不是第二个节点）；合并后"86/107"会明显下降，这是**诚实的数字**，页面上用合并后的数。
  3. 产业页统计条把"企业入口/售后"这类 `channel/service` 节点（3 个）以及 21 条 `sold_through` 单列为"销售入口"，不混进"产业关系"。
- **验收**：同一概念在网络中只有一个节点；`家用房间空调` 只有一个产品节点；全网络单一连通分量（不含明确标注的独立子图）；每家企业所在节点能走到上下游。
- **复现**：用 2026.5 的 topic id 集合作基线，对 2026.6 求连通分量与"新增节点是否与旧节点有边"。

#### P0-3 "产业上下游"页面的承诺与内容不一致（3/5 商品 0 家企业）· [静态] 截图 + [亲验] 数据

- **建议**：企业数为 0 时，标题换成真实能提供的价值（"查看这件商品的工序、设备类别和上下游材料"），"企业官方入口"相关文案只在 `organizations > 0` 的商品出现；0 家企业时把"0 家企业"换成一个**研究者可用的动作**（"提交可补充的企业"见 ⑥ 的最小方案）。

- **成本**：S（文案/条件渲染）。可在展位前做，风险低。

### P1（展位后或有时间做）

#### P1-1 同一物品既是某工序的输入又是其输出（2 环）· [亲验]

- **统计**：手机 8 处，电动自行车 8 处，其余 0。例：手机 `摄像头镜头 ↔ 准备光学与感光部件`、`图像传感器 ↔ 准备光学与感光部件`、`外壳与结构件 ↔ 结构平台集成`；电动车 `通用电动自行车 ↔ 电检与功能测试`、`通用电动自行车 ↔ 附件、包装与出库`、`动力电池包 ↔ 电检与功能测试`。
- **机理**：检验/测试/包装类工序"输入=输出"，投影时用同一个物品 ID 表示前后两种状态。
- **影响**：选中该工序时，同一节点同时出现在"上游"和"下游"两栏；电动车的**成品**还会出现在自己多道工序的上游，直接破坏"上游/下游"含义。
- **建议**：投影时给"输出态"生成独立节点（如"检验合格的摄像头镜头"）或对此类工序只保留输出边；成品只作为最后一道工序的输出。
- **验收**：2 环数为 0；成品节点入度 > 0、出度 = 0。
