## UI作用说明、地图与分类（来自用户回答，所选原文段落）

1. UI 交互细节问题：
你的 UI 不只是交互细节上的问题。比如，将鼠标移到一个按钮时，它会有一个状态的转变，鼠标在按钮上时，会时刻浮现那种状态。这个设计可以解决很多信息展示的问题，包括那些防御性文本和解释性文本。
比如解释一个东西的详细作用，不应该直接贴到框里，而是当鼠标移上去后，按钮亮起来，再待一会儿，才会解释出那些详细的文本。
举个例子：在“数据与指南”中选择“一组示范指南”，当鼠标移到“查看这组指南”按钮上并停留一会儿时，才会显示“从出口归类和监管条件触发再检验”等目的说明。

2. UI 尺寸与逻辑设计问题：
你的 UI 大小，还有一些逻辑设计也有问题。(a) 世界地图抓取：我觉得目前这个项目比较明显的一个亮点是世界地图。但在我操作过程中感觉抓取并不准确，可能需要优化一下逻辑。
(b) 国家选择高亮：选择国家后为什么会显示一个方框？你目前只在少数国家上实现了高亮功能，大多数国家点击后不能高亮，而是显示一个方框。

3. 产品分类标准：
我不知道目前世界上有没有现成的产品分类学说、现成标准，或者一些新提出的方法。就是说对于产品提出一个梯段、梯阶（比如 T1、T2、T3）或者别的分类方式，现成的那种都可以。我举个例子：手机就是最终产品，它很少再被加工成供应链的别的端，基本就是供应这个产业的末端，直接卖给消费者的产品。它的上一级产品是 CPU 或者屏幕总成，直接组成手机，不会再有更多的下游或上游。那手机我就可以把它定义为最终产品、终端产品，而上游的 CPU 和屏幕，我就可以定义为组装件。但是，我想对绝大多数产品实现这种比较明确清晰的分类标准，请你找一下有没有什么好的办法。
