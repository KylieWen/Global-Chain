## 0. 先理解：我们在为什么而做

### 0.1 项目与赛道

- 项目：**GlobeChain**，参加**大工黑客松 S2 · 奇绩创坛赛道「为现实打个补丁」**。
- 赛道精神是"给现实打一个具体、小而有效的补丁"：不追求大而全，而是对准一个真实、具体、可感知的痛点，把它解决到能演示、能复现。
- 技术栈：pnpm 11.19.0 workspace 模块化单体 + Node（>=20.9，本机 v24）+ TypeScript；`apps/web` 为 Next.js 15 App Router + React 19（RSC 为主，地图等少量 client 组件）；`packages/` 含 `contracts`（Zod 契约）、`domain`（只读仓储 + 20+ 查询）、`db`（fixture 加载器，**非真实数据库**）、`map`（**空壳**）、`ui`。
- 数据：纯本地不可变 JSON fixture，active release 为 `globe-chain-smartphone-2023.16`；当前仅 1 个商品 `generic-smartphone`、4 组贸易指南、约 9 个国家有地图/账本数据。
- 测试：Vitest，25 个测试文件。CI（`.github/workflows/ci.yml`）：frozen install → release verify → lint → typecheck → test → build，**无部署 job**。

### 0.2 所有者的初衷（这是产品的灵魂，不要做偏）

> **GlobeChain 是一个"全球商品供应链与贸易数据可视化平台"。它要做的，是把一件普通人每天在用、却看不见其来处的商品（第一部用智能手机），沿着"矿产 → 材料 → 部件 → 成品 → 国家 → 市场"完整地、可视化地讲清楚：锂从哪来、钴从哪来、芯片在哪造、在哪组装、卖到哪里、各国之间的贸易长什么样。**
>
> **进出口贸易指南（关税/手续/文件/官方入口）只是这个平台上"一个可供延伸的方向、一个模块"，不是产品的主体，更不是唯一主角。**

- 核心价值是**"把看不见的全球供应链，画成普通人看得懂的地图和路径"**，而不是做一个政策查询表单。
- 受众是普通人、学生、记者、外贸/采购调研者；文案要**通俗、说人话、简化每条功能**，拒绝开发者术语堆砌和 AI 腔。
- 必须诚实：`unknown` ≠ 0，未收录标"待核验"；代表性路线**不是**某批货物的唯一真实路线；海关贸易额**不等于**企业利润；每条事实带来源、年份、单位、`method`、`datasetVersion`、状态。

### 0.3 最高优先级：产品定位已变更，第一步先改 `AGENTS.md`

仓库当前的 `AGENTS.md`、`README.md`、网站首页、提交材料仍把产品写成"**进出口贸易信息查询与指南针**"，把供应链/地图/账本列为"背景研究模块"。**这已被所有者明确推翻。**

### 0.4 评委视角（自检的尺子）

> 说明：目前没有拿到评委的逐字评语，下列维度是按奇绩创坛赛道取向与黑客松通用评审标准、以及对现有材料的诊断归纳的；如所有者后续提供真实评语，以真实评语为准。

评委通常在很短时间内判断：

1. **问题真不真、具体不具体**：是不是一个真实存在、讲得清楚的痛点（"为现实打补丁"的补丁具体是什么）。
2. **完成度与可运行**：是能跑的产品，还是 PPT 产品；能不能照着 README 复现。
3. **演示有没有记忆点**：视频/Deck 能否在前 30 秒抓住人，有没有一张"会说话的图"或一个抓人的数字。
4. **差异化与价值观**：为什么是你、别人为什么没做好；诚实数据（unknown≠0、路线不冒充事实）是本项目最独特的亮点，必须讲透。
5. **技术含量与工程质量**：数据契约、可追溯、可回滚、可复现、测试与 CI。
6. **赛道契合与叙事一致**：网站、Deck、视频、表单、一页简介讲的必须是同一个产品。

现状最大的评审风险是：**材料各说各话（网站/表单/简介是"进出口指南针"，Deck 是"可视化平台"），且现有 Deck 视觉平庸、版式重复、产品截图缩到看不清、把最能打的世界地图藏了起来。**

2. **Demo 演示材料（项目演示视频为必交项）**。
3. **一页项目简介**。

## 3. P0：演示 Deck 整体重构（本轮重点，详细执行）

现有 10 页飞书 Deck 的问题（已逐页诊断，作为反面清单）：

- 第 3/4/6/7/8 页**连续 5 页同一版式**（左编号列表 + 右网页长截图），套模板感重；
- 右侧是**缩小到看不清字的整页长截图**，无信息量也无美感；
- **最有冲击力的世界地图被缩成小图**，"数据可视化平台"却没有一张大而清晰的可视化主视觉；
- 留白失衡（第 2 页下半屏全空），全程念功能清单，**没有大数字、没有记忆点**。

### 3.1 交付形态：为什么是 HTML Deck（重要）

- 你（Codex）**无法操作飞书 Slides**。请在仓库内交付一份**自包含、可直接在浏览器全屏演示、可打印导出 PDF 的 HTML 幻灯片**：`docs/submission/deck/index.html`（内联或本地 CSS/JS，**不依赖外网 CDN、不依赖构建、不引入运行时外部请求**；可用极简原生 JS 实现键盘 ←/→ 翻页、`?print` 或 `@media print` 导出）。
- HTML Deck 的好处：视觉与版式完全可控、可随代码版本化、评委能复现、可直接录进演示视频、可导出 PDF；本身也是前端能力的展示。
- 仓库外那份飞书 Slides 是旧版。**你不需要改飞书**；HTML Deck 定稿后，所有者会让豆包按它 1:1 搬运回飞书/PPTX（需要你在 `assets/` 里把素材和 `deck-script.md` 备齐）。

### 3.3 重构后的 10 页结构（逐页执行；标题用结论式，每页只讲一个观点）

> 叙事主线贴合 0.2 初衷与 0.4 评委逻辑：**钩子 → 具体问题（补丁）→ 产品是什么（地图主视觉）→ 怎么一层层看清商品 → 数据为什么可信/怎么做到的 → 延伸方向 → 现状与未来**。版式至少 5 种，**严禁连续两页同构**。

1. **封面（深底）**：GlobeChain；主标题"看懂一件商品，怎么来、怎么走"；副标"全球商品供应链与贸易数据可视化平台"；底部赛道署名。背景用**极低饱和度、淡化的世界地图/链路线条**（克制，不喧宾夺主），不要纯空深蓝板。
2. **钩子 · 一部手机的旅程（地理路径图）**：横向呈现 **锂·澳大利亚 → 钴·刚果 → 芯片·中国台湾 → 组装·中国大陆 → 市场·全球**，叠淡色世界底图与国家标注；配一句"你手里的手机连接着全世界，这条链你平时却看不见"。**用图形替代旧版四行干文字**，填满版面、重心居中。
3. **问题 · 补丁打在哪（三栏）**：具体三痛点——① 信息散在海关库/产业报告/政策文件，要翻五六个网站，普通人看不懂、研究者靠手工拼；② "代表性产业路线"常被误读成某台手机的唯一真实路线；③ 海关贸易额常被直接当成企业利润。底部一句话点题："缺的不是更多数据，而是把它整理好、讲清楚、不瞎猜的起点。"
4. **GlobeChain 是什么（大图 hero 页）**：一句话"把全球供应链，画成看得懂的地图"。**主视觉用 3.2 的 `map-hero.png` 大图占据 2/3 版面**；用三个小标签点出能力：**拆解树 / 供应链路线 / 账本 + 地图**。这是全场记忆点，地图必须大而清晰。
5. **商品拆解（大图页）**：成品→部件→材料→矿产、8 大组件。主视觉用 `breakdown-tree.png` 的**清晰局部放大**（不是整页缩略）；右侧 2–3 句口语说明："点进电池，能看到原料来自哪些国家、经过哪些加工环节。"底部小字："首个 Demo 聚焦通用智能手机，模型可复用到更多商品门类。"
6. **代表性供应链路线（流程图页）**：以电池为例 **锂/钴 → 材料加工(正负极) → 电芯 → 模组 → 手机组装**，沿用并精修旧版第 5 页那张五段流程（它是旧 Deck 唯一较好的图形），末段用主色高亮；下方三条承诺：每节点带来源与证据等级 / 数量未知不填零 / 不代表某批货唯一真实路径。
7. **国家贸易账本（数据特写页）**：用 `country-ledger.png` 清晰局部，呈现进出口、贸易差额、官方储备、HS 851713 品类观察；强调"贸易额 ≠ 企业利润""每个数字带单位、年份、来源、状态"。**只用真实数据截图，不新造假图表**；若产品内无图表，就用表格局部 + 定性结论，不要编造数字。
8. **可信与技术（架构图页）**：上半一张极简横向数据流图：**本地不可变数据 → 清单(manifest)索引 → Zod 契约校验并冻结 → 只读查询层(20+ 查询) → 服务端渲染 / 本地 d3-geo 地图**；旁注"不可变版本 + 指针发布/回滚、CI 自动校验、断网可演示、无 API 密钥"。下半三条可信承诺：**每条信息带来源/年份/版本；不知道就标"待核验"(unknown≠0)；不把示意当事实、不把贸易额当利润**。用图形承载，不要堆段落。
9. **进出口贸易指南 · 延伸方向之一（左右对照页）**：明确这是平台能力的一个延伸，而非主体。用 `trade-guide.png` 局部 + 四点：编码归类(HS 851713) / 关税核验（未收录标"待核验"）/ 手续与文件 / 官方入口(如 CBP)；小字注明当前覆盖美国进口、德国/欧盟进口、中国出口，不同管辖区分别核验。
10. **现状、边界与未来（结尾深底）**：诚实说明"当前为 **2023 年公开数据 · 单商品示范版本**，覆盖有限"；给出可复用方向（数据模型可扩展到更多商品门类与国家）；收尾金句回到初衷（如"一张地图、一颗拆解树、一本国家账本，先把一件商品讲清楚"）；放**正确的**仓库地址（地址拼写待所有者裁定，先用占位 `https://github.com/<所有者确认的账号>/Global-Chain`，**不要照抄旧版的 NVDIA 拼写**）。

### 3.4 视觉与排版规范（极简 B 端科技风，量化执行）

- 画布 1920×1080（16:9）；支持全屏、键盘翻页、`@media print` 导出 PDF（每页一张 A4 横版）。
- 配色（低饱和蓝，全篇不超过 3 个主色）：主蓝 `#1e5aa8`、亮蓝 `#2d7dd2`、浅蓝底 `#eaf1fb / #f7faff`、深底（封面/结尾）`#16335f` 左右；正文 `#1a2332`、次要文字 `#4a5568 / #718096`；背景以白/极浅灰为主。**禁止**蓝紫渐变、霓虹、玻璃拟态、发光、3D、地球光效、粒子。
- 字体：中文黑体（PingFang SC / Microsoft YaHei / Noto Sans SC）；大数字可用粗体，代码/字段用等宽；全篇不超过两种字体家族。
- 标题结论式、28–40px；正文 16–20px；图注/来源 11–13px；每页正文不超过 6 行，超出就拆页或图形化。
- 高留白但**不允许大片空白失衡**：主视觉/图形要真正填满版面，重心居中或对齐明确栅格。
- 真实截图要大、清晰、可读；需要时做局部放大，禁止整页长缩略；可用 1px 浅边框/极浅底色承托截图。
- 至少出现**一处大数字钩子**（如"1 部手机 · 8 大组件 · 9 个国家/地区 · 每条数据带来源"，数字必须与真实数据一致，拿不准就改成定性表述），以及**一条权威来源条**（World Bank WDI、UN Comtrade、USGS、IEA、JEITA、SIA、厂商年报、Natural Earth 等）。
- **禁止 emoji**；装饰只用细线、编号、留白、小色块；页脚统一"GlobeChain · 页码 · 数据版本 2023.16（示范数据）"。

## 6. 继续严格生效的工程铁律（未被定位变更推翻）

1. 模块化单体 + 清晰分层；不拆微服务。
2. 代表性供应链路线与官方贸易统计**分开存储、分开校验**，仅通过标准化商品/国家/年份/版本维度关联。
3. 每条事实带年份/期间、单位、来源、`method`、`datasetVersion`、状态；**unknown ≠ 0**，缺失/未披露/无法匹配/估算/真实为零可区分、前端有不同呈现。
4. 页面/组件/查询**不得硬编码**国家、路线、数字；内容由配置与数据集驱动；手机等只是普通商品，**无商品专属特殊分支**。
5. 数据来源→清洗→标准化→校验→发布可追溯到批次/版本；脚本可重复执行；不可变 release 不得删除或覆盖。
6. 运行时只读 published，只做确定性过滤/排序/汇总/单位换算，不自动生成经济结论；**不接 AI/LLM、运行时外部 API、交易撮合/报价/订单/实时物流**。
7. Zod 契约校验、查询带出处与状态、图表校验单位/年份/口径；测试与 CI 保持绿色。
8. 对外文案通俗、简化；视觉统一为极简 B 端科技风、低饱和蓝、高留白、无冗余装饰。
