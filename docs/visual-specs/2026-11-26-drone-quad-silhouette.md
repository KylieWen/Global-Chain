# 无人机参赛收口前置批次：默认四旋翼剪影规格

日期：2026-11-26  
范围：只调整 `generic-camera-drone` 通过通用外观角色得到的程序化几何、布局与取景；不改 fixture、release、领域查询、其他商品或全站导航。公开站不发布。

## 1. 必须解决的视觉问题

当前默认图的四个桨毂位于中央机身矩形轮廓内部，机臂没有伸出机身外轮廓；两片桨又以垂直交叉的十字表达，叠上其他模块矩形后更像板件堆叠。390 默认态云台标签靠近或压住主体。仅靠既有占高和边距数值达标，不能视为外观验收通过。

## 2. 默认态识别目标

- 1440 与 390 的默认视角均应首先读出「一个中央机身 + 四条向外连接的机臂 + 四组桨叶」，而不是四块叠板。
- 四个桨毂/桨叶组在默认态全部可辨；机臂与中央机身有明确连接，桨毂和主要桨叶轮廓必须超出中央机身投影轮廓，不能继续放在矩形板内部。
- 每组桨叶读作「桨毂 + 两个相对伸出的叶片」，不再用两个垂直交叉的长条形成四叶十字。可用简洁 taper/圆角几何，但不引入外部模型或新依赖。
- 独立云台在默认态有可见的前置/下置吊舱与深色镜头，和中央机身保持可读的轮廓分离；不得完全被机身或矩形模块遮住。
- 上述细节仍是与真实 BOM 节点关联的装饰/角色几何，不新增 BOM 节点，不暗示新的官方部件、材质或供应关系；核心组件不得增加 productId 分支。

## 3. 构图、标签与回归护栏

- 沿用上一阶段验收范围：1440×960、390×844，深色与浅色生产截图；主体整包不触底、不右裁，四边留白均 ≥8%，主体占画布高约 58–72%。
- 移动端默认标签不压主体、不与其他标签叠字；云台标签与主体轮廓保留明确间隙。空间不足时沿用既有标签上限与选中/详情兜底，但不能为达标隐藏当前选中项。
- 390 页面无横向溢出，爆炸滑杆、重置、节点列表仍可操作；至少复核云台相机选中深链与高亮。
- 无人机的配置化 viewer override 可以继续使用；不得改变全局默认机位、手机 `fitZoom=0.72` 或 round-7 透视参数。保留手机 1440/390 对照截图。
- WebGL 回退、减少动态与既有节点语义不回归；不重做数据、不启动光伏/锂电，不做全站视觉改造。

## 4. 定向验证与停点

- 先跑相关契约测试，再构建生产版本并复采默认态、云台选中态、390 深浅和手机对照；不能只看 dev 或量测数字。
- 跑受影响的渲染/主线回归与参赛静态包构建；不重复无意义全量单测，最终全量浏览器回归留到总收尾。
