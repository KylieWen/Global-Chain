# MVP 范围：智能手机全球供应链与国家贸易账本可视化

## 状态

- 状态：已固定（Accepted）
- 固定日期：2026-08-24
- 对象：`generic-smartphone`
- 统计期间：2023 年完整自然年（2023-01-01 至 2023-12-31；数据源与口径见 `docs/adr/0002-published-data-sources.md`）
- 覆盖范围：5—10 个关键国家或地区（具体集合由已发布数据配置确定）
- 供应链节点：6—10 个主要展示节点；第一条完整深挖路径为手机电池

本文件是第一版产品范围的单一事实来源。它不代表已经接入任何外部数据，也不代表下列国家、年份或路线已经被事实数据填充。

## 产品定义

MVP 展示一个不对应任何具体品牌、型号、企业或单部设备的通用智能手机商品对象。`generic-smartphone` 是商品目录中的普通商品记录，不能在代码中成为特殊业务类型；手机的组成、分类映射、路线内容和文案均来自数据与内容配置。

MVP 同时提供两个相互连接但事实来源分离的模块：

1. **商品供应链模块**：展示代表性、简化的生产和流转关系。
2. **国家贸易账本模块**：展示指定国家/地区、指定年份的官方或明确标注口径的贸易和宏观事实。

两者不在运行时自动生成结论，也不把代表性路线解释为唯一真实路线。

## 用户第一次进入网站后的核心路径

```text
首页/项目说明
  -> 选择“智能手机（通用商品）”
  -> 查看手机商品拆解树
  -> 进入“电池”深度路径
  -> 查看代表性供应链节点、国家和流向
  -> 打开某个国家节点详情
  -> 跳转到同一国家/年份的国家贸易账本
  -> 查看进口、出口、商品结构、贸易差额或外汇储备中的已发布指标
  -> 打开来源、口径、method 和 datasetVersion
```

若关联事实不存在，页面显示“未发布/未知”，不补零、不猜测路线、不自动生成解释。用户始终可以回到商品拆解、节点详情和方法说明。

## 商品拆解树

以下是 MVP 的内容配置树，不是代码中的特殊枚举，也不暗示每个品牌或型号使用完全相同的部件：

```text
generic-smartphone：智能手机（通用商品）
├─ battery：电池
│  ├─ lithium：锂及锂化合物
│  ├─ cobalt：钴及钴化合物
│  ├─ nickel：镍及镍化合物
│  ├─ graphite：石墨/负极相关材料
│  ├─ copper：铜箔及导电材料
│  ├─ aluminum：铝箔、外壳或结构相关材料
│  └─ cell-module：电芯、模组/电池包
├─ display：显示屏
├─ processor-memory：处理器与存储器
├─ camera：摄像头
├─ pcb-connector：PCB 与连接器
├─ enclosure-structure：外壳与结构件
└─ sensor-audio：传感器与音频部件
```

每个节点至少包含稳定 `productId`、父节点、显示名称、分类门类、适用年份、来源、method、datasetVersion 和数据状态。拆解树可以在未来增加子节点，但不能要求核心页面为每种商品编写专门分支。

## 电池深度供应链路径

第一版将电池作为唯一完整深挖路径。展示层使用 8 个主要节点，节点内部可以挂载材料或子步骤；这满足 6—10 个主要节点的范围，同时避免把所有材料误画成单一线性路线。

| 节点 | 展示内容 | 事实边界 |
|---|---|---|
| 1. 原料开采 | 锂、钴、镍、石墨、铜、铝等主要材料的开采或初级获得 | 可按材料分支；不表示每个来源都进入同一批电池 |
| 2. 精炼/材料加工 | 锂、钴、镍化合物、石墨、铜/铝箔前体等加工 | 标明材料、年份、来源和加工口径 |
| 3. 正极/负极材料 | 正极活性材料、负极材料及相关配方材料 | 仅展示已整理的代表性关系 |
| 4. 电芯制造 | 电极制备、叠片/卷绕、注液、封装等电芯环节 | 不细化到具体工厂或生产批次 |
| 5. 化成与测试 | 化成、分容、测试和质量筛选 | 若来源未提供数量，数量为 `unknown` 而不是 0 |
| 6. 电池模组/电池包 | 电芯组合、保护电路、模组或电池包 | 与手机装配节点分开 |
| 7. 手机组装 | 电池与显示屏、处理器、摄像头等组件装配成通用智能手机 | 不绑定品牌、型号或企业利润 |
| 8. 出口与消费市场 | 代表性出口关系及消费市场/进口市场 | 贸易金额来自贸易账本或明确来源，不等于销量或利润 |

材料节点可通过内容配置连接到节点 1—3；同一种材料可以有多个来源国家、加工地或替代路线。路线必须标记为“代表性供应链流”，不宣称唯一、完整或实时。

## 覆盖与指标

### 国家/地区

数据策展阶段选择 5—10 个关键国家或地区，选择理由可以是材料来源、加工、组件制造、组装、出口或消费市场角色。国家集合必须来自 `Country` 维度和配置，不得写死在页面或查询中。

### 统计年份

首版固定使用 2023 年完整自然年（2023-01-01 至 2023-12-31）。不混用财年、季度、滚动年度或其他年份；后续增加年份必须创建新的数据集版本。来源不可用或未返回的 2023 观察保持 `unknown`/未发布，不以 0 或其他年份补齐。具体指标、分类和许可证决策见 `docs/adr/0002-published-data-sources.md`。

### 国家贸易账本指标

首版选择以下指标中的一部分，但至少包含进出口总额、商品结构和贸易差额中的可发布项，并在条件允许时加入外汇储备：

- 进口总额
- 出口总额
- 贸易差额/顺差或逆差
- 主要商品结构
- 主要贸易伙伴（如数据可用）
- 官方储备总额（含黄金；如与贸易年份和口径兼容）

每条事实或关系必须带：年份/期间、单位、来源、`method`、`datasetVersion` 和数据状态。`unknown`、`null`、`0` 严格区分：

- `0`：来源明确为零，或经同口径规则验证为零。
- `unknown`：未提供、未匹配、无法判断或不适用。
- `null`：数据结构中的空值，仅表示该字段没有值；发布前必须同时有状态或原因，不能把裸 `null` 当作业务语义。

## 两个模块如何连接

供应链模块和贸易账本模块共享标准维度，但不共享事实表：

```text
Product / ProductClassification
          + Country
          + Year / Period
          + DatasetVersion / ContentVersion
                    |
       +------------+------------+
       |                         |
SupplyChainRoute/Flow       TradeFact
代表性内容事实              官方统计事实
```

连接规则：

1. 供应链节点/流使用稳定 `productId`、`countryId`、年份和 `contentVersion`。
2. 贸易事实使用稳定 `productId`（或分类编码映射）、`countryId`、年份和 `datasetVersion`。
3. 跨模块跳转只传递标准 ID、年份和版本上下文；不使用名称模糊匹配。
4. 路线存在不代表贸易事实存在；贸易事实存在也不证明路线中的具体企业或批次。
5. 版本不兼容或没有对应事实时，显示差异说明或“未发布/未知”。

## 必须提供的页面/内容能力

- 商品概览与拆解树。
- 电池 8 节点代表性供应链流程或表格。
- 节点详情：国家、材料/货物、生产环节、方向、年份、来源、method、datasetVersion、状态和限制说明。
- 国家节点详情及到贸易账本的跳转。
- 基础国家贸易账本：已发布的进出口总额、商品结构、贸易差额和外汇储备子集。
- 来源、口径、计算方法和版本详情。
- `unknown`、`null`、`0`、估算和保密状态的不同呈现。

本轮只定义文档范围，不实现以上页面。

## 第一版成功标准

1. 用户首次进入后能够沿“通用智能手机 → 拆解树 → 电池 → 国家节点 → 国家账本”完成核心路径。
2. 电池路径有 6—10 个主要展示节点，并覆盖材料、开采、加工、正/负极、电芯、模组、组装和出口/消费市场阶段。
3. 覆盖 5—10 个已配置的关键国家或地区和一个完整统计年份。
4. 所有展示的重要事实或关系均可打开来源、口径、`method`、`datasetVersion` 和状态说明。
5. 贸易金额、供应链示意和利润/成本概念在界面与文案中明确分离。
6. `unknown`、`null` 和 `0` 在数据、查询、图表和导出中保持语义不变。
7. 增加第二个商品节点只需新增目录、分类映射、路线内容和指标配置，不修改核心页面分支。
8. 在有数据缺口时，系统诚实显示缺口，不以页面默认值或运行时生成结论填补。

## 明确不在 MVP 范围内

- 每个手机品牌或型号的不同供应链。
- 每个具体工厂、订单、批次或实时物流追踪。
- 覆盖所有国家的所有商品和所有年份。
- 精确到单部手机的成本、国内增加值或企业利润。
- 运行时 AI、LLM、聊天、问答或自动生成地缘政治结论。
- 为手机单独设计页面体系、复杂地图和未经验证的高密度实时图层。

## 后续商品的结构不变量

加入汽车、电脑、光伏板或咖啡时，以下结构不能改变：

- `Product`、`Country`、`ClassificationCode`、`Year/Period`、`Unit` 和版本/来源模型。
- 供应链代表性流与官方贸易事实分开存储、分开校验。
- 每条事实或关系的年份、单位、来源、method、datasetVersion 和状态要求。
- 配置驱动的拆解树、路线节点/边、指标定义和页面渲染方式。
- `unknown`、`null`、`0` 的严格语义以及非利润推断边界。

后续商品只应新增数据、分类映射、内容和经过审核的文案；除非出现新的领域事实类型，不修改核心页面或数据库结构。
