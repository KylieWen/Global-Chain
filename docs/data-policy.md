# GlobeChain 数据政策

## 目标与适用范围

本政策适用于供应链路线内容、国家贸易账本、商品分类、宏观指标、图表导出和所有用于支撑页面文字的事实。目标是让每个发布值可解释、可引用、可复核，并清楚区分统计事实、人工整理和示意内容。

## 允许的数据类型

1. 官方公开统计或带明确口径的机构数据。
2. 有出处的人工整理内容，用于代表性供应链节点、环节和流向。
3. 由已发布事实按确定性规则预先计算的汇总、余额、排名或占比。

不允许在运行时调用 AI/LLM 生成经济结论，也不允许把未经审核的网络内容直接作为事实发布。

## 来源优先级

优先使用官方统计机构、国际组织、政府部门和有明确方法与版本的公开数据库；其次使用能够提供原始文档、发布日期、许可证和口径说明的行业/学术来源。来源冲突时保留各自事实和口径，不能静默合并；选择一个用于默认展示时记录选择理由。

每个 `Source` 至少记录：发布机构、名称、链接或文档标识、发布日期、获取时间、许可证/使用条件、统计口径、覆盖期间和备注。

## 数据生命周期与可追溯性

```text
采集原始快照 -> 清洗 -> 标准化 -> 分类映射 -> 验证 -> 人工复核 -> 发布
```

- 原始快照不可变，保存哈希和获取时间。
- 每个转换步骤记录输入/输出批次、脚本或规则版本、参数、执行者和异常。
- 验证失败的数据停留在候选批次，不进入 `published`。
- 发布采用版本号和变更说明；保留历史版本，支持重现和回滚。
- 页面和导出显示数据集/内容版本及生成时间。

## 必备事实字段

任何可展示数字、比例、排名或有方向性的路线事实/关系都必须关联：年份/期间、单位（不适用时显式标记）、来源、`method`、`datasetVersion` 和数据状态。金额还必须有币种和统计概念；数量必须有数量单位；路线内容必须有适用期间、内容版本和证据引用。

## 缺失、零值与估算

`unknown` 不等于 `0`：

- 只有来源明确为零，或在同一统计口径和验证规则下推导为零，才使用 `0`。
- 未提供、未匹配、不可判断或不适用使用 `unknown`，不参与数值合计。
- 保密隐去使用 `withheld`。
- 估算使用 `estimated`，并保留方法、输入和误差/限制说明。
- 校验失败使用 `invalid`，不可发布。

UI 必须让这些状态可见；图表不能把未知静默画成零或空白而造成误解。

## 标准化与单位

- 国家使用稳定内部 ID、ISO 代码和别名映射；名称匹配必须可审计。
- 商品使用内部 ID 与分类体系/版本/代码的显式映射；禁止按名称猜测跨体系等价。
- 金额保留原始币种和原始值；换算后的统一币种值必须带汇率来源、日期和规则版本。
- 数量和金额的精度、舍入和合计规则写入数据集说明。
- 年份、财年、季度或滚动期间不能混用；期间粒度必须显式记录。

## 统计口径与解释边界

- 海关进口/出口、国际收支、外汇储备等概念分别建模并标注，不以一个数字替代另一个概念。
- 贸易顺差/逆差必须说明是出口减进口、使用何种单位和是否经过换算。
- 海关贸易金额不等于企业收入、成本、利润或国内增加值；页面文案和导出中不得暗示等价关系。
- 代表性供应链流是整理后的示意，不是唯一真实路线、实时物流或某一批次证明。

## 质量校验

发布前至少执行：必填字段与类型检查、国家/商品/分类外键检查、年份和期间检查、单位与币种检查、重复键检查、数值范围和符号检查、余额与进出口一致性检查、来源/版本完整性检查，以及代表性路线节点/边的方向与证据检查。

校验规则版本化；规则变更可能产生新数据集版本。抽样复核应覆盖高金额、异常变化、估算值、未知值和跨模块关联。

## 发布、修订与下线

- `draft`：编辑中，不对普通用户展示。
- `validated`：通过自动校验并完成必要人工复核，等待发布。
- `published`：当前可见版本。
- `deprecated`：历史或被替代版本，仅用于审计与复现。
- `invalid`：校验失败，禁止发布。

来源修订、分类体系升级或口径变化应发布新版本并保留变更说明；不要静默改写已发布历史。撤下错误数据时保留撤下原因和替代版本。

## 许可、隐私与安全

仅使用许可允许的公开数据和人工内容；保留归属和原始链接。首版不采集个人信息、不处理订单级敏感数据、不上传未授权的商业数据。访问凭据和内部审核信息不得进入公开导出或前端 payload。
