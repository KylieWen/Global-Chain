## 每次恢复的执行顺序

1. 读根目录 `AGENTS.md`、推荐六篇项目文档、本文件和 `WORKPLAN.md`，再看本聊天最新用户补充。保留用户最新决定。
2. 只读检查 Git 工作区、当前分支和最近检查点。不要覆盖用户修改，不要把已有录音/视频等无关未跟踪文件加入提交。
3. 调用 Codex app 的 `get_usage_limits`。优先 `rateLimitsByLimitId`，适用窗口 remaining=100-usedPercent，空值表示不可用，不表示零；额度为账户共享。
4. 有充足额度时启动一个只读额度监测子智能体，每约 120 秒检查一次，剩余 <=15% 时通知主智能体。单次等待不超过 60 秒；只有阈值、显著变化或失败才报告。若工具不可用，在每个实质工作批次边界主动复查并记录，不能宣称严格实时保护。
5. 依据工作清单推进可验收的小批次；独立任务使用子智能体，并明确文件归属，避免重复写文件。先整合仍在运行的子任务，不重复启动。
6. 完成相关静态检查、契约/单元测试与实际网页核验；发布前执行项目最低质量门槛。记录真正运行的结果，不沿用旧报告的通过结论。
7. 每批次更新本文件：已完成、正在做、下一步、验证命令/结果、失败原因、当前提交。只提交本轮相关代码和文档，不改既有不可变 release，不强推，不擅自上线或联系他人。
8. 额度触线时先协调子任务收束，保存可运行成果。未完成代码和未通过检查必须如实记录；不要为了提交假称通过。恢复入口随提交保存，记录的上一提交允许落后一条。
