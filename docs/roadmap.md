# GlobeChain 路线图

## 现状与原则

截至 2026-08-25，项目已完成最小工程骨架、通用数据契约、mock 商品 fixture、只读 fixture loader、领域查询层、首个无地图 Web vertical slice，以及 2023 年通用智能手机 published 数据快照。国家贸易账本与代表性电池供应链路线均已提供可解释展示和逐记录 provenance；数据库、地图和运行时外部 API 仍未开始。本路线图按“先建立可追溯的数据与内容基础，再扩展覆盖面”的顺序安排，避免在没有口径和数据治理的情况下先做地图和高密度图表。每个阶段都应保持模块化单体，不以微服务为前置条件。

## 阶段 0：决策与基线（已完成）

交付：产品边界、架构、领域模型、数据政策、UX 流程、路线图和协作规则（本批文档）。

退出条件：商品、国家、年份、来源、method、datasetVersion 和状态的命名约定确定；MVP 已固定为 generic smartphone；选定一个主要统计口径；确认推荐技术栈与许可证检查清单。

## 阶段 1：最小工程骨架（已完成，待首个提交）

范围：初始化 TypeScript/React/Next.js 单体应用、pnpm workspace、schema 校验的占位边界、配置目录、测试/构建基础检查和发布版本概念的目录约定。PostgreSQL migration 目录已建立，但尚未创建实际迁移。

不做：地图、外部数据自动接入、复杂权限、AI 服务、手机专属页面。

退出条件：本地可启动占位应用；根目录 lint/typecheck/test/build 命令可重复执行；后续仍需在阶段 1 的下一子阶段完成维度和事实 schema，以及虚拟数据集的 draft/validated/published 流程。

## 阶段 1A：核心数据契约（已完成）

范围：在 `packages/contracts` 中定义手机 MVP 和未来商品通用的类型/schema，覆盖商品、国家、期间、供应链流、贸易观察、宏观指标、来源、证据、内容步骤和数据集版本；用测试固定 `unknown`、`null`、`0`、来源和版本语义。

退出条件：smartphone 和第二个测试商品可以使用同一套契约；schema 测试通过；不创建页面、地图、数据库或外部数据接入。

## 阶段 1B：mock 商品 fixture（已完成）

范围：以同一套 `ProductFixtureSchema` 创建 `generic-smartphone` 和咖啡样例，覆盖商品树、国家节点、生产活动、代表性流、分类映射、贸易观察、宏观指标、来源和警告；所有样例明确标记为合成 `mock`/`unknown` 数据。

退出条件：两个商品均可独立校验；ID 和引用无悬空；`unknown`、`null`、`0` 语义不被混淆；新增商品不修改核心 schema。

## 阶段 1C：只读 fixture loader 与领域查询（已完成）

范围：manifest 驱动的只读 JSON loader、schema/version/status 边界、深度冻结的 in-memory repository，以及商品目录、拆解树、供应链故事、节点详情、国家账本和 provenance 查询。

退出条件：文件系统逻辑与领域查询分层；默认只读取 `published`，draft 必须显式预览；手机和咖啡使用同一查询 API；loader、查询和构建检查通过。详细接口见 `docs/phase4-data-access.md`。

## 实现阶段 5：Web 首条可用路径（已完成本地联调）

范围：将查询服务接入 Next.js 服务端页面，提供商品目录、商品概览/拆解树、供应链路径、节点详情、国家账本和 provenance 页面；页面只消费查询服务，不直接读取 fixture JSON；开发环境显式展示 draft 预览提示，生产环境默认只读 published。

不做：地图、外部 API、数据库查询、利润推断、运行时 AI/LLM、实时物流和真实统计数据接入。

退出条件：手机和咖啡复用同一套路由与组件；`unknown`、`null`、`estimated`、`withheld`、draft 状态有明确呈现；关键路径可导航；lint、typecheck、test、build 通过。

## 阶段 2：单商品供应链试点

范围：以 generic smartphone 为商品对象，人工整理一条有限范围的代表性路线；先完成电池从材料到手机组装/出口与消费市场的深挖；录入国家节点、生产环节、货物、方向、来源、method、期间、datasetVersion 和内容版本；实现非地图的流程/表格视图与详情抽屉。

退出条件：用户可查看路线并核验每个节点/边；新增第二条路线只改数据/配置；页面无国家和数字硬编码；未知与零值视觉上可区分。

## 阶段 3：国家贸易账本试点

范围：接入一个经审核的公开统计快照（本阶段已采用 2023 年 WDI + UN Comtrade 快照，不做实时同步），覆盖 9 个国家/地区；实现进口、出口、商品结构、顺逆差和官方储备（含黄金）的清晰口径展示。

退出条件：每个指标带单位、币种、期间、来源、状态和版本；余额计算可复现；统计事实与路线事实物理分离；来源修订能产生新版本。首份 fixture 已满足这些条件，下一步是页面口径呈现和更广商品/伙伴覆盖。

## 阶段 4：跨模块连接与发布质量

范围：商品/分类编码、国家和年份的统一筛选与跳转；版本一致性提示；导出携带 provenance；增加重复键、单位、范围、余额一致性和跨模块契约测试；基础审计日志与回滚。

当前进度：第 14 阶段已完成首个通用研究快照导出，包含供应链、贸易账本、材料观察、来源、证据和缺口，并同时携带数据集版本与内容版本。统一筛选、版本差异比较和回滚界面仍待后续阶段实现。

退出条件：从任一模块能在保留上下文的情况下进入另一模块；找不到事实时显示未知/未发布而不猜测；同一输入版本可重建同一结果。

## 阶段 5：覆盖面与性能扩展

范围：加入咖啡、光伏板、能源等商品及长期商品门类；扩充国家和年度；在查询证据充分后再引入图表优化、预计算和地图组件；完善可访问性、缓存和监控。

退出条件：新增商品无需修改核心页面分支或数据库结构；性能指标由真实查询测量；地图/高密度图表仍显示来源、状态和代表性声明。

## 阶段 6：后续研究模块（不承诺时间）

在数据质量、方法和用户需求成熟后，再评估成本、国内增加值、利润区间、情景分析或更细粒度供应链。任何估算都必须独立于官方贸易事实，公开输入、假设、误差和不可比性；不把估算结果包装成企业实际利润。

## 跨阶段风险与缓解

- **口径混用**：强制统计概念、单位和版本字段；冲突来源并列展示。
- **代表性路线被误读为唯一事实**：路线视图持续显示示意声明、范围和证据。
- **未知被当成零**：状态枚举、数据库约束、前端徽标和测试共同防护。
- **商品扩展触发代码分支**：配置驱动目录、分类映射和通用渲染组件。
- **数据修订不可复现**：原始快照不可变、转换步骤版本化、发布版本可回滚。
- **过早复杂化**：先单体和单商品，只有真实需求出现后才引入微服务、地图或高成本依赖。

## 每阶段通用验收

文档更新、schema/迁移可重复执行、静态检查和测试通过、关键页面无硬编码事实、来源与版本可见、未知/零/估算状态可区分，并记录尚未解决的问题。
