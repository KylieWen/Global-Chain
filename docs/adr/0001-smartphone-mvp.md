# ADR 0001：将智能手机设为第一版 MVP 商品

- 状态：Accepted
- 日期：2026-08-24
- 决策者：GlobeChain 产品与架构负责人
- 关联范围：`docs/mvp-scope.md`、`docs/product-brief.md`、`docs/architecture.md`、`docs/domain-model.md`、`docs/data-policy.md`

## 背景

GlobeChain 需要用一个可控范围验证两个核心模块：代表性商品供应链流，以及按国家和年份组织的贸易账本。若第一版同时覆盖很多商品、所有国家或品牌级供应链，将在数据口径、分类映射、来源审计和 UX 验证尚未稳定时过早扩大复杂度。

智能手机拥有清晰的多层商品拆解和跨国家生产环节，适合作为验证对象；但它必须被建模为通用商品，而不是任何具体品牌、型号、企业或单部设备。

## 决策

将第一版 MVP 正式固定为：

> “智能手机全球供应链与国家贸易账本可视化”

具体约束如下：

1. 商品 ID 使用 `generic-smartphone`，名称为“智能手机（通用商品）”。
2. 商品拆解至少包含：电池、显示屏、处理器与存储器、摄像头、PCB 与连接器、外壳与结构件、传感器与音频部件。
3. 电池是第一条完整深挖路径，覆盖锂、钴、镍、石墨、铜、铝等材料，以及原料开采、精炼/材料加工、正极/负极材料、电芯制造、电池模组、手机组装、出口与消费市场。
4. MVP 使用一个完整统计年份，覆盖 5—10 个关键国家或地区，展示 6—10 个主要供应链节点。
5. 国家账本展示已发布的进出口总额、商品结构、贸易差额和外汇储备中的一部分指标；具体指标以来源完整性和口径兼容性为准。
6. 供应链路线和贸易统计分开存储、分开校验；只通过标准化商品、国家、年份和版本关联。
7. 所有事实或关系必须包含年份、单位、来源、`method`、`datasetVersion` 和数据状态。
8. MVP 不包含品牌/型号路线、工厂/批次追踪、实时物流、单部手机成本、企业利润、运行时 AI 或自动地缘政治结论。

## 理由

- 智能手机同时包含原材料、化学材料、电子部件、结构件和组装环节，可以验证多层商品拆解模型。
- 电池路径能在有限节点数量内展示从矿产到成品的完整生产阶段，适合验证代表性路线声明和证据链。
- 通用商品对象避免把页面和数据库绑定到单一品牌或型号，保留后续扩展到其他商品门类的能力。
- 一个年份和 5—10 个国家/地区可以控制首版数据整理和审核成本。
- 供应链事实与贸易事实分开，有助于避免把示意路线、海关金额和企业利润混为一谈。

## 备选方案与否决原因

### 具体品牌或型号作为 MVP

否决。会引入品牌差异、供应商保密信息和型号变体，使代表性路线被误读为单一真实路线，并破坏配置驱动的通用模型。

### 一开始深挖所有手机部件

否决。先用完整拆解树建立导航，只有电池进入材料到组装的深度路径；其余部件保持可扩展的概览级内容。

### 一开始覆盖所有国家和所有商品

否决。会放大分类编码、统计口径、缺失值和来源审核风险，无法验证核心 UX。

### 实时物流或工厂/批次追踪

否决。这超出被动式可视化边界，也不是公开统计和人工内容能够稳定支持的首版能力。

### 使用运行时 AI 生成解释

否决。最终产品边界明确排除 AI/LLM、聊天、问答和运行时文本生成；所有文案和结论必须来自人工内容、公开数据或预先计算结果。

### 先拆微服务

否决。当前没有容量、团队隔离或部署边界需求；模块化单体更容易保持统一版本和可追溯发布。

## 数据与架构影响

### 商品目录

新增一个普通 `Product` 记录 `generic-smartphone`，并通过配置表达拆解树。组件节点使用稳定子商品 ID 和分类映射，不增加手机专属代码分支。

### 供应链事实

使用独立的 `SupplyChainRoute`、`SupplyChainNode` 和 `SupplyChainFlow` 记录电池路线。每个节点/关系带年份/期间、单位（如适用）、来源、`method`、`datasetVersion`、内容版本和状态；数量未知时保持未知。

### 贸易事实

使用独立的 `TradeFact` 记录国家/地区、商品或分类编码、年份、进口/出口/余额/储备等指标、数值、单位、币种、统计概念、来源、`method`、`datasetVersion` 和状态。

### 跨模块关联

通过 `productId`、`countryId`、`year/period`、分类映射和版本上下文进行显式关联。关联失败显示“未发布/未知”，不得以名称匹配、默认值或推断路线补齐。

### 空值语义

- `0` 表示经过来源或同口径规则确认的真实零值。
- `unknown` 表示未提供、未匹配、不可判断或不适用。
- `null` 只表示结构字段没有值；对外发布时必须伴随状态或原因，不能作为“零”的别名。

## UX 影响

首次进入路径固定为：通用智能手机 → 商品拆解树 → 电池深度路径 → 国家节点详情 → 同年份国家贸易账本 → 来源/口径/版本详情。路线页面必须持续标注“代表性供应链流”，贸易账本必须显示统计概念和指标口径。

## 后果

### 正面

- 范围明确，能在单个商品上验证端到端数据和 UX。
- 电池路径提供从原料到消费市场的完整示例。
- 通用商品与配置驱动设计为汽车、电脑、光伏板和咖啡保留扩展路径。
- 供应链内容、贸易统计和利润概念保持清晰边界。

### 代价与限制

- MVP 不能回答品牌级、型号级或工厂级问题。
- 单一统计年份不能代表长期趋势。
- 5—10 个国家/地区的选择可能造成覆盖偏差，必须公开选择标准和缺口。
- 同一材料可能存在多条替代路线，代表性路线需要显式说明取舍。
- 外汇储备与商品贸易不一定同口径或同频率，只有在方法和年份兼容时才展示。

## 变更规则

在 MVP 验收前，新增品牌、型号、实时物流、成本/利润估算或运行时 AI 均视为范围变更，必须新增或修订 ADR，不得通过临时页面分支实现。新增商品门类原则上只新增数据、分类映射、内容配置和经过审核的文案。

## 验收依据

以 `docs/mvp-scope.md` 的成功标准和 `docs/data-policy.md` 的发布规则为准。实现阶段仍须遵循模块化单体、分层、来源追踪、版本化和 `unknown`/`null`/`0` 语义约束。
