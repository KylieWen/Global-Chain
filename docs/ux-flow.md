# GlobeChain UX 流程与信息架构

## 设计目标

让跨境采购和外贸调研人员在不阅读长篇方法论的情况下，先按“商品 + 国家/地区 + 进口/出口方向”获得可执行的核验路径，再用商品供应链、国家账本和地图理解背景。界面先面向桌面信息密度设计，同时保持基础响应式。

## 顶层信息架构

```text
首页/项目说明
├─ 进出口贸易指南（主入口）
│  ├─ 商品 + 国家/地区 + 方向查询
│  ├─ 关税/税费核验
│  ├─ 手续与文件清单
│  └─ 官方入口与复核日期
├─ 商品背景
│  ├─ 商品概览
│  └─ 代表性供应链流
├─ 国家贸易账本
│  ├─ 国家年度概览
│  ├─ 进口/出口与伙伴
│  └─ 商品结构与宏观指标
└─ 方法与数据
   ├─ 来源与版本
   ├─ 指标定义
   └─ 数据政策/限制
```

页面通过通用路由参数或状态传递 `product_id`、`country_id`、`year` 和版本；不得把国家、路线或统计数字写入组件常量。

## 关键用户流程

### 流程 A：从商品查看代表性供应链

1. 用户选择商品、年份/期间和数据版本。
2. 商品概览显示商品门类、分类编码映射和覆盖范围。
3. 供应链视图按生产环节展示国家节点、货物名称和方向；以“代表性示意”标签持续提醒边界。
4. 用户打开节点/流详情，看到来源、内容版本、适用期间、整理说明和未知字段。
5. 用户点击国家或商品，跳转到对应国家账本或商品结构，并保留筛选上下文。

### 流程 B：从国家查看贸易账本

1. 用户选择国家和年份；页面显示统计口径和数据版本。
2. 先展示进口、出口、余额/顺逆差，再展示主要伙伴和商品结构。
3. 用户切换商品、伙伴或期间，图表和表格同步更新。
4. 用户打开指标定义，看到单位、币种、计算方式、来源和状态。
5. 对估算、保密、未知或无数据结果显示明确徽标和文本，不画成零。

### 流程 C：跨模块核验

用户从供应链国家节点进入国家账本，或从贸易商品进入供应链内容。系统展示关联的商品 ID、国家 ID、年份和版本；若不存在对应事实，显示“未发布/未知”，不推断缺失路线或金额。

## 页面结构建议

### 通用页头

项目名称、当前模块、商品/国家/年份选择器、数据版本入口、方法说明入口。选择器内容来自已发布维度数据。

### 事实视图

核心图表/表格、单位和期间、数据状态徽标、来源与版本抽屉、方法说明链接、最后更新时间。图表旁提供可读的文本摘要和导出元数据。

### 路线视图

首版可使用节点-边流程图或表格，不要求先实现地图。节点显示国家、环节和货物；边显示方向、说明和证据。若路线只是多来源整理，明确显示“代表性路线，不代表唯一真实流”。

## 状态与异常呈现

- 加载：保留筛选上下文，显示数据集版本占位。
- 无数据：说明“该维度尚无已发布数据”，不要显示 0。
- `unknown`：显示“未知/未提供”及原因（未收集、未匹配或不适用）。
- `0`：显示“0”，可查看来源确认。
- `estimated`：显示估算徽标、方法和限制。
- `withheld`：显示“因来源规则未披露”。
- 版本不一致：阻止无提示的合并，要求用户选择同一版本或显示差异说明。
- 校验/发布错误：普通用户看到稳定错误提示；内部日志保留批次和规则信息。

## 可访问性与可读性

- 不只用颜色区分顺差/逆差、未知和估算；同时使用文字、图标或纹理。
- 所有图表有标题、单位、期间、文本摘要和表格替代视图。
- 筛选器可键盘操作，国家/商品名称支持别名但显示标准名称。
- 大数字显示原始精度与舍入规则入口，避免把 `1.2B` 当作精确值。

## 内容语气与免责声明

文案陈述“数据显示/来源报告/本路线整理为”，避免“证明了唯一供应链”“带来某企业利润”等因果或确定性表达。每个模块提供方法与限制入口，页内关键图表附近提供简短提示。

## 当前不实现的 UX

本阶段不创建地图页面、不做实时刷新、不加入聊天入口、不做手机专属信息架构、不根据用户问题自动生成结论。先通过静态/配置驱动的流程和表格验证信息架构。
